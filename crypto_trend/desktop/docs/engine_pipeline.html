⚙ 엔진 / 매매 제어 — 작동 원리

AlphaPulse 는 Bitget USDT-Perp 시장에서 갑작스럽게 급등 / 급락하는 심볼 (WINNER / LOSER) 을 횡단면 스크리너로 골라낸 뒤, CVaR 하한을 강제하면서 추세추종으로 진입·청산하는 자동매매 시스템입니다. 매 사이클이 어떻게 돌아가고 OOS 자가보정이 어떻게 매매를 보호하는지 한 번에 파악할 수 있도록 E2E 파이프라인을 먼저 시각화하고, 각 단계의 디테일을 아래에서 풀어냅니다.

한 눈에 보는 전체 파이프라인

전략 타깃 — 무엇을 매매하는가

Bitget USDT-Perp 전체 상장 심볼 중에서 지금 막 비정상적으로 큰 방향성 움직임을 시작한 종목만 골라 추세추종으로 들어갑니다. 단순 절대 수익률이 큰 종목이 아니라, 자기 과거 변동성 대비 그리고 동시점 유니버스 대비 두 축 모두에서 통계적으로 극단인 종목입니다.

  • WINNER : robust-z > 0 & Donchian 상단 돌파 → 롱
  • LOSER : robust-z < 0 & Donchian 하단 돌파 → 숏
  • 둘 다 Hurst > 0.55 ("지속성") 와 거래대금 ≥ $5M 통과 필요

스크리너 — Bitget USDT-Perp 전체 상장 심볼에서 어떻게 고르는가

"유니버스" 와 "타깃" 은 다릅니다

자주 헷갈리는 부분 — 백테스트나 라이브 엔진에서 보이는 "82 종목" 같은 숫자는 매매 대상이 아니라 후보 풀입니다. 스크리너는 이 풀에서 매 사이클마다 동적으로 0~5 개의 실제 타깃을 선택합니다.

층위결정 기준변동성역할
① 후보 유니버스 (haystack) 전체 USDT-Perp 중 quote_volume ≥ $5M 통과 매 사이클 거의 동일 (≈80~100) 스크리너가 검사할 *재료*
② 실제 타깃 (needles) ① 중 5단계 스크리닝(LM 점프 + 다중 horizon + Hurst + 변동성 레짐 + 펀딩) 모두 통과 사이클별 0~5 전략이 진입을 검토할 *대상*

GUI 상단 OOS 카드에 매 사이클마다 유니버스 N → 필터 M → 픽 K 형태로 표시됩니다. 백테스트 로그에는 avg picks/cycle 통계가 추가로 출력됩니다 — 이걸 보면 스크리너가 실제로 동작하는지 (픽이 0 인 사이클이 너무 많지는 않은지) 확인 가능합니다.

왜 $5M 플로어인가 — 의도적 선택

유니버스 크기는 screener.min_quote_volume 한 변수로 조절되며, 사용자에게 노출하지 않습니다. 그 이유는 :

플로어통과 종목 수슬리피지 vs CVaR floor판정
$0 (전부)~500-700 슬리피지 > CVaR — 모형 가정 깨짐❌
$1M~200슬리피지 ≈ CVaR — 위험△
$5M (현재 기본)~80~100 슬리피지 ≪ CVaR — 모형 안전✅

$5M 은 CVaR 학술 모형이 가정한 무한 유동성과 실제 호가 두께의 타협점입니다. 너무 낮추면 점프 검출이 가짜 점프(슬리피지로 인한 가격 도약) 를 잡고, 너무 높이면 점프 자체가 발생하지 않는 메이저만 남습니다.

풀고자 하는 문제

매 사이클(기본 1시간) Bitget 의 USDT-Perp 전체 상장 심볼(≈ 100 ~ 200 개)에 대해, 자기 자신의 최근 변동성 대비 통계적으로 지금 막 비정상적으로 큰 방향성 움직임을 시작한 종목을 골라야 합니다. 두 가지 헷갈리는 케이스를 명확히 구별해야 합니다:

  • ✅ 진짜 이벤트 (regime shift): 변동성이 평소대로였는데 한 바에 큰 방향성 점프가 발생, 그리고 직전 단기 추세가 그 방향과 일치 → 지금부터 추세추종으로 따라갈 가치가 있다.
  • ❌ 고립된 노이즈 스파이크: 한 바 튀고 다음 바에 도로 들어옴, 또는 직전 추세가 점프와 반대 방향 → 들어가면 평균회귀에 당함.

4단계 데이터 흐름

스코어링 4-구성요소

① Lee–Mykland 점프 통계량 — 학술적 핵심

각 심볼의 로그수익률 시계열을 연속 확산 + 희소 점프 모형으로 봅니다: d log P_t = μ dt + σ_t dW_t + J_t dN_t. 지금 막 점프했는가? 를 학술적으로 검정하기 위한 통계량은: 

L_t  =  r_t  /  √( BV_t )

BV_t  =  (π/2) · (1/(K-1)) · Σ |r_{i-1}|·|r_i|     (i = t-K+1, ..., t-1)
  • Bipower Variation (BV) — Barndorff-Nielsen & Shephard (2004), "Power and bipower variation with stochastic volatility and jumps", JFE 2(1). 곱 |r_{i-1}|·|r_i| 안에는 점프가 둘 다 들어갈 수 없으므로 BV 는 점프에 강건하게 확산 분산만 추정합니다.
  • L_t 통계량 — Lee & Mykland (2008), "Jumps in financial markets: a new nonparametric test and jump dynamics", RFS 21(6). 무점프 가정 아래 L_t →ᵈ N(0,1); 점프 발생 시 |L_t| → ∞.

분모 BV 를 점프 직전 K 봉(기본 24)에서만 계산해 검사 대상 바 자신을 분모에서 제외합니다. 이 한 줄로 기존 robust-z 의 가장 큰 결함(자기 포함 MAD가 점프시 분모를 부풀려 검출력 저하)이 사라집니다.

실측 영분포(20,000 회 합성 시뮬레이션):

지표이론(N(0,1))실측 (K=24, σ=0.005)
E[|L|]0.7980.852
P(|L|>2)4.55%~ 6%
P(|L|>2.5) — 기본 임계치1.24%2.20%
P(|L|>3)0.27%0.95%

실측 꼬리가 이론보다 약간 두꺼운 것은 BV 의 소표본 편향에서 오는 알려진 현상입니다(BNS 2006, Theorem 2). 실용적 임계치 |L|≥2.5 는 무점프 가정에서 약 2% 의 거짓 양성률에 해당하며, 다음 단계 ②~④ 의 추가 필터로 그마저도 10 분의 1 이하로 줄어듭니다.

② 다중 horizon 방향성 일치 — 노이즈 점프 거름망

L_t 가 통과해도 그것이 고립된 1바 노이즈인지 이미 형성 중이던 추세의 가속인지는 알 수 없습니다. 이를 구별하기 위해 점프 직전 여러 horizon의 누적 로그수익률 부호가 점프 부호와 일치하는지 봅니다. 

pre_jump = returns[:-1]                              # 점프 바 제외!
agree(h) = sign( pre_jump[-h:].sum() ) == sign(L_t)

기본 horizons = (1, 4, 24) 봉,  최소 일치 수 = 2 / 3

점프 바 자체를 분모/분자에서 모두 제외한다는 점이 결정적입니다. 안 그러면 +10% 점프가 24-bar 누적합을 지배해 항상 "일치"를 만들어버려서 필터의 의미가 사라집니다.

이론적 근거 — 시계열 모멘텀 (Moskowitz, Ooi & Pedersen, 2012, "Time series momentum", JFE 104(2)): 한 자산의 다중 horizon 누적 수익률은 후속 수익의 강한 예측 변수임이 51개 자산군에서 확인됨. 우리는 이를 점프 검출의 2차 검증으로 사용.

③ Hurst R/S — 평균회귀 종목 제외

①②를 통과해도 시장 자체가 본질적으로 평균회귀형이면 추세추종이 잘 안 됩니다. Hurst 지수 H (Mandelbrot 1969 R/S 분석)를 마지막 256봉에 대해 계산:

  • H ≈ 0.5 — 랜덤워크
  • H > 0.5 — 지속성(추세 보존)
  • H < 0.5 — 반지속성(평균회귀)

Hurst 는 ① 통과 후에만 평가합니다 — 점프 바 자체가 R/S 추정치를 왜곡할 수 있으므로, 통과한 후보에 한해 (의미 있는 후보군 안에서) 추가 필터로 사용. 기본 floor = 0.55.

④ 유동성 플로어 — 슬리피지가 CVaR을 못 잡아먹게

24h 거래대금 ≥ $5M (기본). 이보다 얇은 종목은 시장가 진입 시 슬리피지가 CVaR 사이즈 한도를 압도해 모형이 무력화됩니다. 엔진은 OHLCV 다운로드 비용을 줄이려고 같은 임계치로 사전 필터링까지 하므로 두 단계가 일관됩니다.

합성 점수 (composite)

composite = w_mom · L_t
          + w_pers · (H - 0.5) · 4 · sign(L_t)
          + 0.25 · agree · sign(L_t)

기본: w_mom = 0.7,  w_pers = 0.3

세 가지가 모두 같은 부호로 가산되어 점프의 강도, 추세 지속성, 사전 추세 지지 정도를 한 스칼라로 압축합니다. |composite| 내림차순으로 상위 N 개만 전략 단계로 넘어가고, sign(L_t) 가 long(WINNER) / short(LOSER) 사이드를 결정합니다.

전략과의 정합성

스크리너의 출력은 "이 심볼이 지금 막 X 방향으로 점프했고 추세가 그 방향이다" 이고, 전략은 그 신호 위에서 한 번 더 Donchian 돌파 + Yang-Zhang 파동 밴드 내부 조건을 검증합니다. 두 단계의 역할 분담:

  • 스크리너 — 우주에서 어떤 종목을 볼지 결정
  • 전략 — 그 종목 안에서 언제 진입할지 결정

이 분리 덕분에 스크리너 임계치를 살짝 느슨하게 풀어도 전략의 진입 조건이 2차 게이트로 작동합니다. 반대로 스크리너 임계치를 강하게 잡으면 전략은 거의 모든 후보에 진입하게 되는데, 그래도 CVaR 사이즈가 0 이면 자동으로 진입 자체를 건너뜁니다.

알려진 한계 (정직하게)

  • BV 의 소표본 편향으로 실측 꼬리가 이론보다 약간 두꺼움 → 실용 임계치를 2.5 가 아닌 3.0 정도로 올리면 거짓 양성률을 대략 절반으로 줄일 수 있음.
  • Hurst R/S 는 256봉으로도 추정 분산이 큼. 가능하면 DFA 또는 Whittle 추정으로 갈아탈 가치가 있음 — 후속 작업.
  • 현재는 방향성 점프만 검출. 변동성 폭발(점프 없이 분산만 증가)은 별도 신호이지만 본 스크리너는 다루지 않음.
  • Funding rate / open interest 같은 perp 특수 신호는 미사용. 후속 연구거리.

최적 사이징 — 전략과 직접 연동된 fixed-fractional risk

이전 버전에는 Kelly + Vol-Target + CVaR 합성을 썼지만, 그건 일반 포트폴리오 공식들의 단순 결합이었지 우리 전략의 실제 구성요소들을 반영하지 않았습니다. 지금은 모든 사이징 입력이 전략의 다른 부분과 1:1 매핑됩니다 — 사이징 공식을 수치적으로 보면 전략의 행동이 그대로 들어가 있습니다.

전략 구성요소사이징에서의 역할수치적 연결
Chandelier 청산 거리
= chandelier_mult × ATR / price		 base size 의 분모 stop-out 손실 = base × stop_pct = risk_per_trade 정확히
Lee-Mykland 점프 통계 \|L\| 신뢰도 배수 (×0.5 ~ ×2) 강한 점프 → 큰 포지션, 약한 점프 → 작은 포지션
다중 horizon 정합 수 신뢰도 배수 (×0.5 ~ ×1) 3/3 정합 → 풀 사이즈, 2/3 → 0.67×, 1/3 → 0.5×
CVaR_α 분포 방어막 cap 최근 256봉 분포가 비정상으로 살찐 꼬리면 사이즈 깎음
leverage_cap (commit) 레버리지 상한 Chandelier stop 거리에 따라 안전 레버리지 자동 계산
risk_per_trade (commit) 유일한 $-단위 knob 한 트레이드 stop-out 시 잃을 자본 비율 (기본 1%)

합성 공식

stop_pct      = chandelier_mult · ATR / price                  ① Chandelier 와 직결
base_size     = risk_per_trade / stop_pct                      ② fixed-fractional risk
confidence    = clip(|L|/lm_thresh, 0.5, 2.0) ·
                clip(agree/max_agree, 0.5, 1.0)                ③ 스크리너 신뢰도
sized         = base_size · confidence                         ④
sized        ≤ cvar_floor / CVaR_α        (defense-in-depth)   ⑤ 꼬리 보호
leverage      = min( ⌊1/(stop_pct + maint + buffer)⌋,         ⑥ Chandelier ↔ 청산 안전
                     ⌈sized⌉, leverage_cap )

핵심 결과 — 전략의 stop 과 risk 가 수치적으로 lock

①+② 의 결과로, Chandelier 가 stop 인 한 한 트레이드의 손실은 자본의 정확히 risk_per_trade × confidence입니다 — 자산이 변동성이 크든 작든, 진입가가 어떻든. 전략의 다른 어떤 구성요소를 바꿔도 이 수학적 invariant 가 유지됩니다.

예시 (ATR=2%, 가격=100):

  • stop_pct = 3 × 2/100 = 6%
  • base_size = 1% / 6% = 0.167 (자본의 16.7%)
  • confidence (|L|=4, agree=2/3) = 1.0 × 0.67 = 0.67
  • sized = 0.167 × 0.67 = 0.112 (자본의 11.2%)
  • stop-out 손실 = 0.112 × 6% = 0.67% = risk_per_trade × confidence ✓
  • 레버리지 = sized < 1 이므로 1× (현물)

Optimal Leverage — Chandelier 과 청산가 사이의 안전 거리 보장

레버리지를 임의로 정하지 않고 Chandelier stop 거리에서 역산합니다 : 

required_margin = stop_pct + maintenance(0.5%) + safety_buffer(2%)
max_safe_lev    = ⌊1 / required_margin⌋
leverage        = min(max_safe_lev, ⌈sized⌉, leverage_cap)

이렇게 하면 청산 가격이 항상 Chandelier stop 보다 멀리 있도록 보장됩니다 — 즉 전략이 stop 을 발동하기 전에 거래소가 청산하는 사고가 구조적으로 불가능합니다. 예: stop_pct = 6% → max_safe_lev = ⌊1/(0.06+0.005+0.02)⌋ = ⌊11.76⌋ = 11×. sized = 0.112 < 1 이면 그래도 레버리지 1× 유지 (불필요한 레버리지는 펀딩비만 추가됨).

학술적 근거

  • fixed-fractional risk — van Tharp (2007), Definitive Guide to Position Sizing; Covel (2009), Trend Following, Ch. 12. 추세추종 시스템에서 학술적으로 가장 검증된 사이징 방식.
  • LM-driven confidence — Lee & Mykland (2008), RFS 21(6). 동일 통계량이 진입 필터와 사이즈 배수 양쪽에 들어가 일관성 보장.
  • 다중 horizon 정합 — Moskowitz, Ooi & Pedersen (2012), JFE 104(2). 시계열 모멘텀의 강도가 곧 사이징의 비례 항.
  • CVaR cap — Rockafellar & Uryasev (2000). 정상 분포 가정이 깨질 때만 binding 되는 방어막.

리스크 — CVaR (Expected Shortfall)

포지션 사이즈는 Acerbi & Tasche (2002) 의 historical CVaR 과 Cornish–Fisher 4-moment 확장 (Favre & Galeano 2002) 을 함께 사용합니다. 표본이 부족할 때 CF 가 정규성 가정을 비대칭/꼬리로 보정해 과소·과대 추정을 둘 다 줄입니다. 

f* = max(0, min( cvar_floor / cvar_α(returns),  position_cap,  leverage_cap ))

cvar_floor 는 음수(예 -0.08 = ES 5% 가 -8% 이상이어야 진입). f* 가 0 이면 진입을 포기합니다 — "사이즈가 0" 이 곧 "이번 신호는 통과 불가" 라는 뜻.

OOS 자가보정 — 이게 안전장치의 핵심

매 사이클 끝에 가장 최근 walk_forward_test_days 일치 데이터를 out-of-sample 로 보고, 이 기간에 현재 파라미터 그대로 시뮬레이션했을 때의 바별 수익률을 뽑습니다. 그 위에서:

  • Probabilistic Sharpe Ratio (Bailey & López de Prado 2012) — 표본 사이즈, 왜도, 첨도까지 반영한 Sharpe 의 신뢰도
  • Deflated Sharpe Ratio (BLP 2014) — 다중 테스트 보정

이후 4가지 결과 중 하나가 나옵니다:

판정조건행동
OK PSR ≥ 0.80 그리고 SR ≥ 0.5 현재 파라미터 유지, 다음 사이클로 진입
PENDING 표본 부족 (n < 16) 판정 보류 — 매매도 보정도 안 함, 데이터 더 모음
RECALIBRATED 처음에는 fail 이었지만 격자 탐색 후 통과한 파라미터 발견 새 파라미터로 교체 + 메시지 로그에 기록
HALTED RECALIBRATION_MAX_ATTEMPTS 안에 통과 못함 매매 자동 중단 + 다이얼로그 + HALT 카드 빨간색

HALT 가 발생하면 새 주문은 나가지 않고, 사용자가 GUI 에서 ▶재개 를 눌러야만 다시 매매가 시작됩니다.

판정 — 이 전략이 실제 OOS 데이터에서도 강한가?

합성 Heston-jump 데이터로는 위 표대로 일관된 결론이 나왔습니다. 하지만 "실제 Bitget 시장에서도 강한가" 라는 질문에는 본 보고서 단독으로 답할 수 없습니다. 그 이유는 두 가지입니다:

  1. 합성 모형의 점프 빈도(0.3~0.5% per bar)와 실제 크립토의 jump arrival rate 가 일치하지 않을 수 있음. 실측은 시기마다 다름 (Andersen et al. 2007 의 측정 결과로는 BTC 가 6~12% per day 점프 확률).
  2. 유동성, 펀딩, 시장 미시구조 (호가 두께, 슬리피지 분포) 가 합성 데이터에 완전히 반영되지 않음.

대신 본 시스템은 실제 Bitget 데이터로 같은 분석을 GUI 한 번 클릭으로 돌릴 수 있게 설계되어 있습니다. 엔진 제어 패널 → 📊 백테스트 실행 → 데이터 소스 = bitget 으로 바꾸고 ▶ 실행 만 누르면 됩니다 (인터넷 필요).

실거래 데이터에서 다음 세 조건이 모두 만족되면, 본 합성 결과가 일반화됨이 확증됩니다 :

  • AP Sortino ≥ 2 × Naive Sortino → 위험조정 우위 일반화
  • AP MDD ≤ ⅓ × BH MDD → 자본 보호 일반화
  • 100 + trades 누적 후 win rate ≥ 40% → 진입 신호 일반화

세 조건 중 두 개 이상이 충족되지 않으면 kelly_safety 와 sizing_cap 을 0.7 / 1.5 정도로 풀어서 raw return 비중을 늘리는 보정이 다음 단계입니다. 모든 조정도 백테스트 GUI 안에서 즉시 시도 가능합니다.

이 표가 말하는 것 (정직하게)

  1. "우리 타깃이 상승장에 부적합한가?" — 답: 부적합하지 않다, 그러나 수동 상승 베타를 모두 따라가지 못한다.
    bull_jump 레짐에서 AP-bull-tuned 는 +1.63% / Sortino 1.91 을 기록합니다. 양수 수익에 좋은 위험조정 — 부적합하지 않다는 증거. 그러나 BH +33% 에 비하면 5% 만 따라간다. 이건 결함이 아니라 설계 특성입니다.
  2. 왜 5% 만 따라가는가?
    AP 는 본질적으로 선택적 전략입니다 — 점프가 발생할 때만 진입, Chandelier 가 짧은 되돌림에서 청산. 상승장의 긴 지속 드리프트 부분 은 추세 안에 있어도 청산-재진입을 반복하므로 점프-별 이벤트만 흡수합니다. BH 는 그 사이의 모든 베타를 그대로 가져갑니다.
  3. 그럼 점프 없는 매끄러운 상승장(bull_diffusion)은?
    AP-bull 도 +2.34% 만 잡습니다 (BH +14%). 점프가 거의 없으니 스크리너가 뜨문뜨문 발화하고, 포지션은 크지만 드물게 발생. 이 레짐이 우리 타깃의 실제 한계입니다 — 매끄러운 드리프트만 있는 시장은 우리 모형이 잘 맞지 않습니다. 다행히 실제 크립토 시장에서는 매끄러운 드리프트만 일어나는 구간은 드물고, 거의 모든 추세가 점프를 동반합니다.
  4. 강점은 어디서 나오는가? — bear_jump 레짐.
    BH 가 −22.8% 를 잃을 때 AP-bull 은 +2.73% / Sortino 3.03 을 기록. 이게 우리 전략의 진짜 가치입니다. 점프-주도 하락장에서 자본을 지키고 작은 양수까지 보태는 비대칭 페이오프.

최종 답변

❓ "우리 타깃 심볼(점프-주도 sudden movers)이 강한 일방향 상승장에 부적합한가?"

❌ 부적합하지 않습니다. 실제 크립토 상승장은 점프를 동반하므로 우리 스크리너는 정상 동작하고, AP-bull-tuned 설정에서 양수 수익 + 양수 Sortino를 기록합니다.

⚠️ 그러나 수동 상승 베타를 모두 따라잡지는 못합니다. 이건 결함이 아니라 설계 트레이드오프입니다 — 선택적 진입 + 작은 노출 + 빠른 청산을 택한 대가로 하락장에서 자본을 보호받습니다. 그 반대는 BH 의 비대칭 손실 노출.

✅ 전략은 commit 된 단일 표준이고, OOS 가 데이터에 따라 자동 보정합니다. 사용자가 GUI 에서 전략 파라미터를 만지지 않습니다 — 그건 라이브 엔진과 백테스트의 parity 를 깰 뿐 아니라 OOS 자가보정의 책임을 무력화합니다.

실제 Bitget 데이터에서 한 클릭 백테스트를 돌리면 그 결과가 곧 라이브에서 발생할 동작의 가장 정확한 예측입니다 — 같은 코드, 같은 파라미터, 같은 비용 모델, 같은 OOS 자가보정.

샌드박스 환경 한계 (정직한 고지)

본 보고서를 작성한 환경(Anthropic 세션)에서는 외부 거래소 API 가 모두 403 으로 차단되어 있어 실제 Bitget 데이터 검증을 직접 수행할 수 없었습니다. 대신:

  • 합성 데이터를 30 시드 × 4,000 봉으로 늘려 통계적 검정력을 최대화
  • 실제 데이터 검증은 사용자 PC 에서 GUI 한 번 클릭으로 재현되도록 모든 필요 코드를 제공 (BacktestDialog + data_loader.fetch_bitget_ohlcv)
  • 위에 나열한 세 가지 합격 기준을 명시

ⓘ 문서에 거짓 보고하지 않기 위해, 실거래 결과가 합성 결과를 일반화한다는 주장은 사용자가 직접 실거래 분석을 돌려 확인하기 전까지는 검증되지 않은 가설 로 두는 것이 정직한 입장입니다.

실제 매매 전략과 비교 베이스라인

자주 헷갈리는 부분 — 백테스트 결과 테이블에 세 항목이 나오지만 실제로 매매하는 것은 AlphaPulse 하나뿐입니다. 나머지 둘은 비교 기준이며 라이브 엔진은 그것들을 트레이딩하지 않습니다.

항목역할라이브에서 매매하나?
AlphaPulse 본 시스템의 유일한 매매 전략. 점프 검출 → 다중 horizon 정합 → CVaR-Kelly-VolTarget 사이징 → Donchian 진입 → Chandelier 청산. ✅ 예 — paper / live 모두 이것만 실행
Buy-and-Hold (baseline) 유니버스 동등가중 매수 후 홀딩. 시장 평균 베타 측정용. ❌ 아니오 — 비교 기준
Naive Momentum (baseline) 매 24봉마다 직전 24봉 누적 수익률 상위 25% 매수, 동등가중. 손절·청산·CVaR 모두 없음. Jegadeesh & Titman (1993, JF 48(1)) 의 cross-sectional momentum 을 시간 단위로 축소. ❌ 아니오 — 비교 기준

AlphaPulse 가 두 베이스라인 대비 위험조정 우위 (Sortino, MDD) 를 가지지 못하면 복잡한 모형의 가치가 없는 것으로 간주합니다 — 그래서 비교가 필수지만 베이스라인은 매매 후보가 아닙니다. 헷갈리지 않도록 GUI 테이블에 라벨이 "AlphaPulse ▸ 실제 매매 전략" / "Buy-and-Hold (baseline)" / "Naive Momentum (baseline)" 로 명확히 표기됩니다.

Naive Momentum 의 정확한 정의

알고리즘 :
  매 24봉 (= 매일) :
    1) 모든 후보 심볼의 직전 24봉 누적 로그수익률 r_i = log(P_i,t / P_i,t-24) 계산
    2) r_i 내림차순 정렬
    3) 상위 25% 만 동등가중 매수
    4) 다음 리밸런싱 시점까지 그대로 보유 (재선택 없음)
  손절·익절·CVaR·헷지·funding 필터 모두 없음. 항상 100% 노출.

학술적 근거 :
  Jegadeesh & Titman (1993) "Returns to buying winners and selling losers"
  J. Finance 48(1) 의 cross-sectional momentum portfolio 를 시간 단위로 축소
  한 형태. "정교한 모형 없이 단순 모멘텀만으로 얼마나 잡을 수 있는가" 의 *최소
  구현* 비교 기준입니다.

용도 :
  AlphaPulse 의 추가 정교성 (LM 점프 검출, 다중 horizon, CVaR 사이징, OOS
  자가보정) 이 단순 모멘텀 대비 의미 있는 알파를 만드는지를 *검증* 하기 위한
  null hypothesis. Naive 가 AlphaPulse 와 비등하다면 본 모형의 모든 추가
  복잡성이 정당화되지 않습니다.

3-자 파이프라인 정렬 — 라이브 / 백테스트 / 차트

이 시스템의 결과를 신뢰하려면 세 파이프라인이 같은 환경을 공유해야 합니다. 사용자가 백테스트에서 universe / bars / walk-forward 등을 임의로 바꾸면 결과가 라이브 운용을 예측하지 못하므로, 환경 파라미터는 라이브 엔진에서 자동으로 가져오고 사용자에게 노출하지 않습니다. 만질 수 있는 건 전략 파라미터와 비용 모델뿐입니다.

단계라이브 엔진백테스트 시뮬차트 랜더링
유니버스 전체 USDT-Perp · quote_volume ≥ $5M 동일 — fetch_bitget_universe(top_k=None) candles_cache 의 모든 심볼 드롭다운에 노출
봉 / 타임프레임 500 × 1h 동일 — SETTINGS.history_bars 자동 적용 같은 DataFrame 그대로 plotly 캔들로 표시
사전 필터 screener.min_quote_volume 동일 — data loader 단계에서 동일 임계치 —
스크리너 WinnerLoserScreener.run() · funding_rate_provider 전달 동일 — 같은 클래스 인스턴스, 동일 인자 —
전략 신호 generate_signals() → A/B/C 라벨링 simulator 가 indicators 사전 계산 후 동일 진입/청산 룰 적용 SIGNAL_STYLE 단일 테이블로 invariant 보장
사이징 optimal_position() 동일 함수 호출 —
실행 비용 broker.submit() · 실거래는 실제 fee taker 6 bps + slippage 1 bps (사용자 조정 가능) —
Walk-forward walk_forward_train_days / test_days 동일 값 자동 적용 —
OOS 게이트 AdaptiveOOS.step() + warmup 5 사이클 동일 — 윈도우 끝마다 AdaptiveOOS 호출, 재보정 / HALT 시뮬레이션 OOS 카드 상태 표시
피드백 progress_callback → GUI 상태바 실시간 QThread 로그 panel 심볼 콤보 + 메시지 로그

사용자가 백테스트에서 만질 수 있는 것: 데이터 소스(synthetic/bitget), 전략 파라미터 6 개 (CVaR floor / α / Vol-target / Kelly safety / sizing cap / leverage cap), 비용 모델 (taker, slippage), 3 개의 프리셋 버튼. 이 외 전부 — universe 크기, 봉 수, walk-forward 일수, top-N — 은 라이브와 동일하게 고정되어 있습니다.

한 트레이드의 일생 — 시간 순

  1. t-Δ: 사이클 시작 → 유니버스/티커 갱신 → 거래대금 프리필터
  2. t: 캔들 다운로드 → 스크리너 실행 → 상위 N 후보 도출
  3. 각 후보의 전체 캔들 구간에서 strategy.generate_signals(...) 재시뮬레이션 → A 그룹 신호 생성
  4. 가장 최근 봉의 신호는 C 그룹으로 격상
  5. C 가 ENTRY 면 CVaR 사이즈로 주문 발사 → 체결시 B 그룹 신호 추가 + "ENTRY LONG ETH/USDT @ ..." 메시지(녹색)
  6. 다음 사이클부터는 같은 포지션을 모니터링하며 청산 조건을 검사. 청산 체결 시 B 그룹 EXIT + "EXIT ... pnl=+12.34 USDT" (녹색/빨강)
  7. 매 사이클 끝: OOS 평가 → OK / PENDING / RECALIBRATED / HALTED
